## 실행 방법

이 도구는 **웹 페이지가 없습니다.** 기획서의 운영 기준(내 PC 안에서만 구동, HDX 사내 폐쇄망)에 맞춰 **PC에서 직접 실행하는 Python 프로그램**으로 만들었습니다. 인터넷 연결, 서버, AI 호출이 모두 필요 없고 표준 원문은 PC 밖으로 나가지 않습니다.

### 1. 준비물 (폐쇄망 PC)

| 준비물 | 설명 |
|---|---|
| Python 3.8 이상 | 개발·시험은 3.11 에서 했습니다 |
| openpyxl | 엑셀 입출력용 패키지 1개(+ 의존 패키지 et_xmlfile). **이 저장소 `vendor/wheels/` 에 설치 파일이 들어 있습니다** |
| pypdf | PDF 읽기용 순수 Python 패키지(5.9.0, BSD). `vendor/wheels/` 에 들어 있고, **설치하지 않아도 도구가 그 파일을 바로 불러 씁니다** |
| 이 저장소 폴더 | 「Code → Download ZIP」으로 받은 zip |

Word(.docx) 읽기, DB(SQLite), HTML 보고서는 Python 기본 기능만 씁니다. 추가 설치는 openpyxl 하나뿐이고, PDF 를 읽는 pypdf 는 `vendor/wheels/` 의 파일을 설치 없이 씁니다(원하면 `python -m pip install --no-index --find-links vendor\wheels pypdf` 로 설치해도 됩니다).

### 2. 폐쇄망 PC에 설치하기

1. **인터넷 PC에서 준비** — python.org 에서 Windows 설치 파일(예: `python-3.11.x-amd64.exe`)과 이 저장소 zip 을 받습니다. zip 안 `vendor/wheels/` 에 `openpyxl-3.1.5-py2.py3-none-any.whl`, `et_xmlfile-2.0.0-py3-none-any.whl` 이 들어 있습니다.
   - 다른 버전이 필요하면 인터넷 PC에서 `python -m pip download openpyxl -d wheels` 로 받습니다(순수 Python 패키지라 운영체제와 무관).
2. **사내 반입 절차에 따라** 위 파일을 폐쇄망 PC로 옮깁니다(반입 절차는 기획서 10장 확인 필요 항목).
3. **Python 설치** — 설치 파일 실행, 첫 화면에서 「Add python.exe to PATH」를 체크합니다. 관리자 권한이 없으면 「Install Now」(사용자 설치)로 됩니다.
4. **openpyxl 설치(인터넷 없이)** — 저장소 폴더에서 명령 프롬프트를 열고:

   ```
   python -m pip install --no-index --find-links vendor\wheels openpyxl
   ```

5. **확인** — `python review_tool.py demo` 가 끝까지 돌면 설치 완료입니다.

openpyxl 이 없어도 점검은 됩니다. 이때 회의록 초안은 CSV 로 저장되고, 기준표 엑셀 편집과 판정 되받기는 쓸 수 없습니다.

### 3. 사용법

명령은 저장소 폴더에서 실행합니다(macOS·Linux 는 `python` 대신 `python3`).

| 하는 일 | 명령 |
|---|---|
| 예시 데이터로 전체 흐름 보기 | `python review_tool.py demo` (학습 시연 포함) |
| **Template 학습** | `python review_tool.py learn template 설계표준_양식.pdf --type 설계표준` |
| **기존(승인) 표준 학습** | `python review_tool.py learn standard 승인표준1.pdf 승인표준2.docx` |
| **기존 회의록 학습** | `python review_tool.py learn minutes 기존회의록.xlsx` |
| 학습 현황 보기 / 지우기 | `python review_tool.py learn show` / `learn reset` |
| 표준 점검 | `python review_tool.py review 표준초안.pdf --type 설계표준` (.docx 도 됨. `시험검증표준`, `가상검증표준`) |
| 기존 회의록과 비교 | `python review_tool.py compare 결과\…\회의록초안.xlsx 기존회의록.xlsx` |
| 도구가 읽은 구조 확인 | `python review_tool.py inspect 표준.docx` |
| 평가 기준 꺼내기 | `python review_tool.py criteria export 기준표.xlsx` |
| 고친 기준 다시 넣기 | `python review_tool.py criteria import 기준표.xlsx --reason "고친 이유"` |
| 기준 변경 이력 | `python review_tool.py criteria history` |
| Template 항목 반영 | `python review_tool.py template import Template.docx --type 설계표준 --reason "Template 반영"` |
| 검토자 판정 되받기 | `python review_tool.py feedback 결과\...\회의록초안.xlsx` |
| 보완 후보 보기 | `python review_tool.py improve --html 보완후보.html` |

- **예시 데이터 불러오기** = `demo` 명령입니다. `samples/` 의 가상 표준 2건(`예시데이터_설계표준_정상.docx`, `예시데이터_설계표준_오류포함.docx`)을 점검하고, 예시 판정을 넣어 보완 후보 보고까지 만듭니다. 결과는 `결과_예시/` 에 생기며, 엑셀·보고서 맨 위에 「예시 데이터」 안내가 붙습니다. 시연은 별도 DB(`결과_예시/예시데이터.db`)를 써서 실제 기록과 섞이지 않습니다.
- `review` 결과는 `결과/파일명_일시/` 에 생깁니다: **회의록 초안 엑셀**(지적·위치·수정 요청 문구, 판단 프롬프트 시트 포함), `prompts/` 의 **판단 항목 프롬프트**(항목별 .txt), **점검 보고서 HTML**(브라우저로 열기).
- 판단 프롬프트는 도구가 AI 에 보내지 않습니다. 파일 내용을 복사해 **사내에서 승인된 AI** 에 붙여 넣어 씁니다.
- 기록(기준표 버전, 점검, 판정)은 `data/stdreview.db` 파일 하나에 쌓입니다. 백업은 이 파일을 복사하면 됩니다.
- 기존 회의록의 열 이름이 다르면 `criteria export` 로 꺼낸 기준표의 「회의록열」 시트에서 열 이름을 바꾸거나, 되받을 때 `--map verdict=판정` 처럼 알려 줍니다(열 매핑).

### 4. 내 자료로 학습시키기 (기획서 5.4)

「학습」은 AI 모델 학습이 아니라, **내 PC 에서 내 파일의 구조와 표기 습관을 세어 규칙으로 바꾸는 일**입니다. 인터넷·AI 호출이 없고, 파일 내용은 PC 밖으로 나가지 않습니다.

1. **Template 학습** — 표준 종류마다 양식 파일(.docx 또는 .pdf) 1개를 넣습니다.
   `python review_tool.py learn template 설계표준_양식.pdf --type 설계표준`
   `python review_tool.py learn template 시험검증표준_양식.pdf --type 시험검증표준`
   → 상위·하위 항목 목록과 순서, 「예시)」 표시와 예시 문구, 머리글 자리표시(xx·0000), 개정 이력 칸, 흐름도가 들어갈 절을 배웁니다.
2. **기존(승인) 표준 학습** — 이미 심의를 통과한 표준을 여러 개 넣습니다.
   `python review_tool.py learn standard 승인표준1.pdf 승인표준2.pdf`
   → 용어정의 목록, 사내 문서번호의 **모양**(영문·숫자 자릿수), 표·그림 캡션 방식(예: 괄호 안 캡션), 영문 표기 습관(하이픈 등)을 배웁니다.
3. **기존 회의록 학습** — 예전에 쓴 회의록 엑셀(또는 .docx·.pdf)을 넣습니다.
   `python review_tool.py learn minutes 기존회의록.xlsx`
   → 지적 범주(구분) 이름, 문장 끝맺음(「…바랍니다」「…필요」「…요망」 등), 머리 기호, 열 이름을 배웁니다. 엑셀은 「구분」「해당 절」「검토의견」 같은 열 이름으로 열을 찾고, 못 찾으면 글이 가장 긴 열을 의견 열로 봅니다.
4. **점검** — `python review_tool.py review 표준초안.pdf --type 설계표준`
   학습 결과가 자동으로 적용됩니다. 화면과 엑셀 「정보」 시트의 「학습 프로필」 줄에 무엇이 적용됐는지 나옵니다. 학습 없이 보려면 `--no-profile`.
5. **맞춰 보기** — 같은 초안을 심의한 기존 회의록이 있으면 `compare` 로 일치율(재현율·일치율, 범주별 건수)을 봅니다. 놓친 범주는 기준표 보완(5장)으로 채웁니다.

- 학습 결과는 **`data/profile.json` 한 파일**에 쌓이고 `.gitignore` 로 **저장소에 올라가지 않습니다.** 이 파일에는 사내 용어·지적 문구가 들어 있으니 PC 밖으로 옮기지 마세요. 다른 파일에 두려면 `--profile 경로`.
- 같은 이름의 파일을 다시 학습하면 덮어씁니다. 처음부터 다시 하려면 `learn reset`.
- 학습한 Template 의 항목 번호가 기준표의 「N항」과 다르면(예: 표준 종류마다 안전 항목 번호가 다름) 이름이 같은 항목으로 기준 대상을 옮기고, 그 Template 에 없는 항목의 기준은 「해당 없음」으로 표시합니다.
- PDF 는 Word 의 제목 스타일·표 칸·수식 정보가 없어서, 제목은 「4.1 …」 번호 줄로 찾고 머리글·바닥글(쪽마다 되풀이되는 줄)은 따로 떼어 냅니다. 캡션이 아예 없는 표·그림과 수식 개수는 PDF 에서 알 수 없어 검토자 확인 항목으로 남깁니다. **정확도는 원본 .docx 가 가장 높습니다.**

### 5. 평가 기준 보완하는 법 (추가 댓글 반영, 기획서 5.3)

1. `review` 로 회의록 초안을 만듭니다.
2. 엑셀의 「검토자 판정」 열에 지적마다 **채택/제외**, 「보완 의견」 열에 기준을 어떻게 고치면 좋을지 적고 저장합니다.
3. `feedback` 으로 되받습니다. 같은 파일을 다시 넣으면 덮어씁니다.
4. `improve` 로 **제외가 많은 기준(오탐 의심)** 과 **보완 의견이 달린 기준**을 봅니다. 기준값(최소 판정 건수, 제외 비율)은 기준표 「설정」 시트에서 바꿉니다.
5. `criteria export` 로 기준표를 꺼내 문구를 고치거나, 새 기준 행을 넣거나(점검코드 비움 + 점검 방식 「판단(프롬프트)」), 사용을 N 으로 바꿉니다. 이형 표기·정성 표현·표준번호 형식도 각 시트에서 늘립니다.
6. `criteria import` 로 다시 넣으면 **바뀐 점을 먼저 보여 주고**, 확정하면 새 버전과 변경 이력(날짜·사유)이 남습니다.
7. 채택된 지적은 다음 점검의 판단 프롬프트에 「과거 채택 지적 예」로 들어가 AI 답의 수준을 맞춥니다.
