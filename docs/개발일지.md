### 결정과 이유

- **자료를 저장소에 넣지 않고 학습을 도구 안으로 옮겼습니다.** 수강생이 자기 PC 에서 `learn` 으로 자기 파일을 넣으면 규칙이 `data/profile.json` 한 파일에 쌓입니다. 이 파일은 `.gitignore`(data/, profile*.json 등)로 올라가지 않습니다.
- 「학습」은 모델 학습이 아니라 **세어서 규칙으로 바꾸기**입니다. 문서번호는 번호 자체가 아니라 모양(영문·숫자 자릿수)만 뽑아 정규식으로 씁니다.
- PDF 는 pypdf 를 골랐습니다 — 순수 Python, 의존 패키지 없음(3.10 이하에서 typing_extensions 하나), BSD. Python 3.8 을 지원하는 5.x 마지막 판(5.9.0)을 넣었습니다. zip 인 .whl 을 sys.path 에 넣어 **설치 없이** 불러오므로 폐쇄망 PC 에 파일만 가져가면 됩니다.
- PDF 에서는 표 칸·수식·그림 위치를 알 수 없어, 거짓 지적을 내지 않도록 그 판정은 「검토자 확인」으로 돌렸습니다(수식 개수 → 판단 필요, 캡션 없는 표·그림 → 적합 문구에 한계 명시).
- 표 안의 번호 칸(「5 …」)이 절로 잡히는 문제를 실제 자료에서 발견해, PDF 에서는 상위 절을 「5. …」처럼 점이 있을 때만, 그리고 앞 절보다 3 이내로 큰 번호만 받게 했습니다.
- 양식의 항목 번호가 표준 종류마다 달라, 기준표의 「N항 이름」과 학습한 양식 항목 이름을 맞춰 대상 절을 옮기고 없는 항목은 「해당 없음」으로 두었습니다. 조용히 빼지 않고 회의록·보고서·화면에 무엇을 옮기고 뺐는지 적습니다.
- 공통-3·공통-4 는 원문 기준표에 없던 기준이라 기준표에 **(가정)** 으로 넣었습니다. 예전 버전 기준표(DB)를 쓰는 PC 에도 점검 때 자동으로 채워 넣되 DB 는 바꾸지 않습니다.
- 회의록 문체: 도구 문구(「…해 주시기 바랍니다.」)를 학습한 끝맺음(…필요 / …요망 / …할 것 / …요청 등)으로 바꿉니다. 「…해」로 끝나는 문장만 명사형으로 바꾸고 나머지는 「…야 함」으로 두어 뜻이 흐려지지 않게 했습니다. 회의록 열 이름(구분·해당 절·검토의견)을 학습해 초안 엑셀 열 이름을 맞추고, 겹치는 이름은 바꾸지 않습니다.
- 저장소의 가상 자료는 구조만 흉내 냈고 문구·번호·제목·제품은 모두 지어낸 것입니다(가상 번호 QSP-…).

- **Python 표준 라이브러리 + openpyxl 만** 씁니다. python-docx 대신 zipfile 로 .docx XML 을 직접 읽습니다 — 폐쇄망 반입 파일을 하나라도 줄이기 위함입니다. openpyxl 이 없어도 점검·프롬프트·HTML 은 되고 회의록은 CSV 로 떨어집니다.
- **도구는 AI 를 부르지 않습니다.** 판단 항목은 프롬프트 파일로만 내보냅니다(기획서 2.2). 응답 형식은 「판정 / 근거 위치 / 지적 내용 / 수정 요청」 네 줄로 정해 두어, 2단계에서 되붙이기를 붙일 수 있게 했습니다.
- **평가 기준을 코드가 아니라 기준표(DB 저장, 엑셀로 편집)에 둡니다.** 추가 댓글 요청의 핵심입니다. 문구·사용 여부·대상 절·사전·정규식·기준값·회의록 열 이름은 모두 엑셀에서 고칩니다. 판정 방식 자체(표 번호 연속성 계산 등)는 코드라 「점검코드」로 연결만 합니다. 새 판단 기준은 점검코드를 비우고 「판단(프롬프트)」로 적으면 바로 프롬프트가 생깁니다.
- 기준표를 다시 넣을 때 **바뀐 점을 먼저 보여 주고 확정**하게 했습니다. 모든 버전과 변경(추가·수정·삭제·사용 중지, 날짜·사유)이 이력으로 남습니다.
- **검토자 판정(채택/제외·보완 의견)** 을 회의록 초안 엑셀에서 되받아 기준별로 쌓고, 제외 비율이 높거나 의견이 달린 기준을 보완 후보로 보여 줍니다. 채택된 지적은 다음 판단 프롬프트의 「과거 채택 지적 예」로 들어갑니다 — 기획서의 「기존 회의록을 규칙과 프롬프트 예시로 반영」을 도구 안에서 순환하게 한 것입니다.
- 판정 되받기는 엑셀의 **「순번」 + 「정보」 시트의 검토ID** 로 행을 찾습니다. 검토자가 열 이름을 바꿔도 `--map` 으로 맞출 수 있습니다(열 매핑).
- 제목 인식: Word 제목 스타일(자동 번호 포함)을 우선하고, 스타일이 없으면 「4.1 …」 처럼 번호로 시작하는 짧은 문단을 제목으로 봅니다. 2항 목록의 「1. EXS-…」 같은 번호 줄을 제목으로 오인하지 않도록, 상위 번호는 앞 번호보다 커야 하고 하위 번호는 현재 상위 절 안에서만 받습니다. 실제 문서가 다르면 설정 「번호_제목_인식」을 「아니오」로 바꿔 스타일만 쓰게 할 수 있습니다.
- 캡션: 「표 3의 입력값으로 다시 계산한다.」 같은 본문 문장을 캡션으로 오인하는 문제를 예시 문서에서 발견해, 캡션 스타일이거나 짧고 문장으로 끝나지 않는 문단만 캡션 후보로 보게 고쳤습니다.
- 시연(`demo`)은 별도 DB 를 매번 새로 만들어 실제 기록과 섞이지 않게 했습니다. 실행 결과·DB 폴더(`data/`, `결과/`, `결과_예시/`)는 사내 원문이 담기므로 `.gitignore` 에 넣었습니다.

### 가정

- Template 항목 구성(1~8항 이름)은 제출 원문의 기준 설명에서 옮긴 **가정값**입니다. 6항 이름은 비어 있어 이름 비교를 하지 않고, 8항 Appendix 는 선택 항목(필수 N)으로 두었습니다.
- 표준번호 형식: ISO·IEC·KS·SAE 일반 표기와 **사내 표준 예시 형식 `영문 2~5자-숫자 3~6자리`(가정)** 입니다. 실제 사내 규칙으로 바꿔야 합니다.
- 이형 표기 사전은 원문 예시(ECU ↔ 이씨유)만 넣었습니다. 정성 표현 낱말(양호·적절 등)은 초기 예시입니다.
- 설정의 숫자(짧은 설명 10자, 프롬프트 본문 12,000자, 보완 후보 최소 3건·제외 비율 0.5)는 **임시 기본값**입니다. 근거 있는 값이 아니므로 기준표 「설정」 시트에서 바꿉니다.
- 예시 표준 문서와 인용 번호(EXS-…)는 모두 가상입니다. 파일 이름과 결과물에 「예시 데이터」를 표시했습니다.
- 4-7, 5-3 은 원문 기준이 비어 있어 사용 N 으로 두었습니다. 기준을 채워 Y 로 바꾸면 판단 프롬프트가 생깁니다.
